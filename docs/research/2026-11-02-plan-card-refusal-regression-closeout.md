# Plan-Card Refusal Consistency Regression

Date: 2026-11-02
Project: UNA Unified MCP Scheduling System
Phase: Verified plan-card integration
Workstream: MCP / AI-agent integration
Branch: integration/verified-plan-cards-20261102
Parent checkpoint: 58e3781

## Objective

Ensure that verified schedule cards are not displayed
when the conversational AI refuses to provide a schedule
or does not present a complete verified schedule option.

## CONFIRMED — Step 53

A new regression test discovered a response/UI mismatch.

The deterministic planner returned valid synthetic options,
but the AI answered:

"I cannot provide a schedule."

The application still returned plan_cards.

The new regression test failed, confirming the problem.

## CONFIRMED — Step 54

A conservative answer-to-card consistency guard was
introduced with additional tests.

One new test failed when refusal language appeared
together with verified section IDs.

The refusal regular expression was incorrectly escaped
when generated by the implementation script.

## CONFIRMED — Step 55

The regular expression escaping was corrected.

Observed local results:

- Targeted plan-card tests: 7 passed.
- Assistant test module: 24 passed, 1 skipped.
- Authenticated integration and adapter: 24 passed.
- Complete MCP suite: 128 passed.
- Complete AI-agent suite: 1044 passed, 1 skipped.

The corrected logic suppresses cards in the tested
refusal and incomplete-answer scenarios while retaining
cards for tested valid schedule responses.

## SECURITY AND RELIABILITY

- Deterministic planning remains authoritative.
- The LLM cannot register or enroll students.
- Verified cards remain proposed_only.
- Existing MCP authorization was not changed.
- Existing model-facing redaction was preserved.
- The final answer is checked before cards are exposed.
- No real UNA student data was used.

## LIMITATION

The answer-to-card consistency guard uses conservative
text matching. It does not prove semantic consistency for
all possible natural-language responses.

Further adversarial and browser end-to-end testing is
recommended before any production deployment.
